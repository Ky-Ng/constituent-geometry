# Experiment 15 — Multi-seed sweep on v2 grammar depth-2 random-frame dataset

## Goal

Extend the depth sweep (experiments 14 → depth 1, 09 → depth 3 v1) to the v2 grammar
at depth 2 (`kylelovesllms/hi-hf-v2-frames-d2-k100-random`, random-frame split).
Primary question: does performance degrade between depth 1 and depth 2, and which
architectures are most affected?

## Setup

- **Dataset:** `kylelovesllms/hi-hf-v2-frames-d2-k100-random` (v2 grammar, depth 2, k=100, random-frame split). Already contains adjuncts (199,900 / 200,000 train rows have an Adj/Adv), so no regeneration was needed.
- **Tokenizer:** the **137-token v2 word-level tokenizer** built from `grammar.v2.cfg_vocab` (adjectives + adverbs in-vocab). This replaces the original 58-token tokenizer, which lacked Adj/Adv and produced `<unk>` for adverbs like *gracefully*.
  - seq2seq (vaswani / vaswani_rope): `artifacts/tokenizer/` — built via `python -m src.architecture.build_tokenizer_v2`
  - gpt2_rope (needs `<sot>`): `artifacts/tokenizer_gpt2/` — built via `build_tokenizer_gpt2.py`
- **Architectures:** vaswani, vaswani_rope, gpt2_rope (local `train_*.py`, mirroring 06/07/08)
- **Seeds:** 42–51 (10 seeds)
- **Early stopping:** `ThresholdStopCallback` (`src/training_loops/callbacks.py`) stops each run 1 epoch-boundary after eval exact-match ≥ 0.98 (`--stop-threshold 0.98`). Max 30 epochs otherwise.
- **Model shape:** 4 heads, 4 layers, d_model=128, d_ff=512

## How to run

One-time tokenizer build:

```bash
uv sync   # registers src/training_loops as a package
uv run python -m src.architecture.build_tokenizer_v2 \
    --out experiments/15_multi_seed_grammar_v2_depth_2_random/artifacts/tokenizer
uv run python experiments/15_multi_seed_grammar_v2_depth_2_random/build_tokenizer_gpt2.py
```

Train (packed mode — one job per arch, 10 seeds share one GPU; the tiny model
underuses a single GPU, so packing is faster than array mode and stays well
within the 8-GPU QOS limit):

```bash
sbatch slurm/run_gpu.sbatch experiments/15_multi_seed_grammar_v2_depth_2_random/run.py --arch vaswani
sbatch slurm/run_gpu.sbatch experiments/15_multi_seed_grammar_v2_depth_2_random/run.py --arch vaswani_rope
sbatch slurm/run_gpu.sbatch experiments/15_multi_seed_grammar_v2_depth_2_random/run.py --arch gpt2_rope

# Array mode alternative (one GPU per (arch, seed) pair):
sbatch --array=0-29%9 slurm/run_gpu.sbatch experiments/15_multi_seed_grammar_v2_depth_2_random/run.py
```

`--stop-threshold` defaults to 0.98; pass `--stop-threshold 0` to train the full
30 epochs. Convergence plot:

```bash
uv run python experiments/15_multi_seed_grammar_v2_depth_2_random/plot_convergence.py
```

## Results

All 30 runs early-stopped and reach near-perfect held-out-frame test exact-match.
Final accuracy is saturated for every architecture; the interesting signal is
**convergence speed**, which splits cleanly by positional encoding.

| arch | test exact-match (mean / range) | epoch crossing 0.98 (mean) |
|---|---|---|
| vaswani (sinusoidal) | 0.993 / 0.985–0.999 | **1.06** |
| vaswani_rope | 0.996 / 0.992–0.999 | **0.70** |
| gpt2_rope | 0.994 / 0.984–0.998 | **0.71** |

**Finding:** both RoPE variants cross the 0.98 threshold ~0.35 epochs earlier
than the original sinusoidal Vaswani — vaswani's eval exact-match lingers in the
high-0.95s for a stretch before crossing, while the RoPE models jump straight
through. Final accuracy is indistinguishable (~0.99 for all three); RoPE's
advantage here is *speed of convergence*, not ceiling.
